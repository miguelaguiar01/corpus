# Changelog

The published packages are `@corpus-tool/cli` and `@corpus-tool/workbench`, at one version. This file follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/) and stay below 1.0 while the
contract (`corpus/1`) is the only one.

## [Unreleased]

### Fixed

- A gettext pull no longer fills in the missing forms of a plural entry nobody edited (#981).
- Switching language on a string page shows that language's own text; the editor no longer keeps the previous language's draft (#979).
- Gettext files in Cebuano, Manx, Welsh, Filipino, Hebrew and Latvian (older rule), whose `Plural-Forms` cut across CLDR's categories, now show and write every plural form (#982).
- Rails plurals are checked by the runtime's rule: `zero` is always allowed, and rails-i18n's per-locale rule applies where `Gemfile.lock` lists the gem (#983).
- A target's section whose keys look like plural categories is read as keys unless the source has a plural there, and under i18next a lone `{ "other": … }` is a key; `init` picks i18next for catalogues with plural objects (#984).
- i18next plural keys (`item_one`, `item_other`) are one string per family, so each language gets its own forms (Polish `few` and `many`) and `_zero` is always allowed; pull translations before the first 0.22 push, which re-reads these families from the files (#985).
- Under i18next an unpaired tag such as `<no title>` is text, not a refusal, while `Trans` tags are still compared and `<2/>` for `<2>…</2>` is caught (#986).
- Android strings with an escaped `&lt;…&gt;` or an inline CDATA read as text and build; a pull writes such text escaped (#987).
- Rails keys ending in `_html` are read as HTML: a translation's own tags are accepted, and broken markup in them is still caught (#988).
- An Android app's modules are one project: an `android` source's `path` may list its `res` directories, with `merge`, and a `{ns}` captures a Compose Multiplatform module (#989).
- A Fluent message Corpus cannot read is refused on its own instead of failing its whole file, and the build goes on (#991).
- A glossary term finds its regular inflections (`assassino`: `assassinos`, `assassina`), and `match: "exact"` turns that off for an entry (#1073).
- `corpus validate --server` checks the instance's translations, an exec source's drafts included, and plain `validate` no longer calls a partly checked exec source valid (#1074).
- Fluent's own syntax reads: hyphenated names, nested plurals and selects, string literals, a `#` in a variant, terms, `NUMBER()` and `DATETIME()` (#990).
- A Fluent translation may select on its own variables and keys, as Fluent allows; a select on a variable the source never passes is a warning (#1032).
- A translation that writes a plural as one text, where the source never prints the count, is incomplete rather than invalid (#992).
- A plural written as plain text may print its count, and en-GB beside en needs only the source plural's own categories (#1005).
- `corpus init` writes a config for a Fluent catalogue and for an Android res directory (#993).
- An Android language with a numeric region is read and written as `values-b+es+419`, the directory aapt2 accepts (#993).
- `languageFiles` may map the source language, as `{ en: "templates" }` for Pontoon's layout; a `sourcePath` a source does not read is refused (#994).
- ICU's `selectordinal` reads, validates by each language's ordinal rule, and previews (#995).
- `corpus init` takes a target `.po` as the source where no template is committed, and says when a missing source file is git-ignored (#996).
- Qt: a percentage written `%10` is text, `%n` is a numerus translation's count, and a lookalike `٪n` is refused (#1003).
- Qt: a numerus file short of forms is seeded and named, a source file's English forms are its source plural, and a proposal on Qt text gives the tr() reason; translations of such a source's numerus strings go stale once (#1004).
- Android: a regional language reads and writes each module's `values-ta` where it has no `values-ta-rIN`, as Android resolves it (#1007).
- i18next: a `{{…}}` that holds no name, a Go template's `{{ define "<NAME>" }}`, is a placeholder a translation keeps verbatim, not a refusal (#1008).

## [0.21.0] - 2026-09-29

What nine new projects found: XLIFF, gettext, String Catalogs, Qt Linguist and Rails YAML read natively; counterpart, easy_localization, Rails and Qt as libraries, each plural checked by its own rule; a source's catalogues merged strictly or last-wins; broken seeds in an Invalid queue; and nine projects that push and pull back byte-identical.

### Added

- The wiki's exec section documents the whole contract: every field an export command's entries may carry and what each does, `entities` and `translations`, and every field of the JSON a pull hands an import command on stdin, which ids reach it and which do not. It ends with a worked example, an exporter, a merging importer and their config for a JSON file no adapter reads, which the test suite runs through `build`, `validate`, `pull --check` and `pull` as the page shows them.
- A plural may sit in a select's branch, and a select in a plural's, one level deep: `{gender, select, female {{count, plural, one {…} other {…}}} other {…}}`. Each level is validated, the inner plural's categories against the target language and the select's branches against the source, and previews render through both. The editor shows such a message as nested branches, and the outer argument's chip inserts the inner skeleton, in the target language's categories, into each branch. Discourse's `read_more_MF` strings, refused before, build and validate across its 49 languages with only category warnings. A translation nests as its source does; a plural in a plural, a select in a select, a third level, or nesting in an Android string is refused by name. A `#` in a select within a plural, which FormatJS prints as `#` and messageformat.js as the count, is refused in a translation with `{n}` advised, and in a source is warned by `build`, `push` and `validate` without failing anything, as is a translation that is the source's own text.
- A `yaml` source reads Rails I18n catalogues with no converter: `{ adapter: "yaml", type: "ui", path: "config/locales/client.{lang}.yml" }`, the language as the root key (`pt_BR` through `languageFiles`), a plural hash as one plural, `*_MF` keys as ICU, a key's comment as its note, and anchors and `<<:` merges read once where they are written. Under `library: "rails"` by default. `pull` writes a changed scalar back in its own style, a plural's forms into its hash, and a missing key after its neighbour at the file's own indentation; on Discourse's 96 catalogues (7,988 client and 3,945 server strings) a pull of their own translations leaves every byte as it was. A proposal edits, adds or removes a key in the source file, a removal reaching every target file. `corpus init --messages config/locales/client.{lang}.yml` writes the source, and a YAML file named under the `messages` adapter is pointed at `yaml`.
- A `qt-ts` source reads Qt Linguist `.ts` files with no converter: `{ adapter: "qt-ts", type: "ui", path: "src/lang/app_{lang}.ts" }`, `lupdate`'s template or the source language's own file as the source. A message's id is Qt's identity (context, source and disambiguating comment), or a `qsTrId` message's own `id`; `<extracomment>` and locations are its note, and only finished translations seed. Under `library: "qt"` by default. A numerus message is one plural on `count`, its `<numerusform>`s mapped to CLDR categories through Qt's rule for the language and written back in Qt's order. `pull` splices a changed translation into its `<translation>` alone, escaping as lupdate does, and inserts a message a target lacks where the template has it; on qBittorrent's 63 `src/lang` files it builds 2,502 strings and 119,752 seeds, validate finds 88 placeholder defects (`% 1`, `%22` for `%2`) that printf read as text, and on all 120 of its catalogues a pull of their own translations leaves every byte as it was. A translation that drops `%n` from every form is invalid, and one whose forms no plural gives back is not seeded, said once by `build` and as a `validate` warning, and left as the file has it. `corpus init --messages src/lang/app_{lang}.ts` writes the source, and a Qt `.ts` named under the `messages` adapter is pointed at `qt-ts`.
- A String Catalog key's verbs are the arguments the code passes (`notifications.label.favorite %lld`), carried with the string as `arguments` (additive) and honoured wherever a translation is validated: the CLI, a push's seeds, the editor, a transition and an agent's draft. A translation may pluralise on one the English text does not print (German's `hat favorisiert`/`haben favorisiert` where English says "starred"), and a verb written at that position must be the key's type, so `%@` for an `lld` count is refused. Ice Cubes now validates with only its two real defects. The string API and the MCP `get_string` return them as `arguments`, so an agent knows it may pluralise on one.
- An `xcstrings` source reads Apple's String Catalog, the default for every Xcode project since Xcode 15, with no converter: `{ adapter: "xcstrings", type: "ui", path: "App/Localizable.xcstrings" }`, one file for every language. `variations.plural` and `substitutions` are plurals of printf branches, device and width variants one string each (`key [device:iphone]`), and `comment` the note; stale keys and `shouldTranslate: false` are left out, and only units translated throughout seed. `pull` writes changed units back in Xcode's own layout; on Ice Cubes (732 strings, 19 languages in one 2.2 MB file) a pull of every language's own translations leaves the file byte-identical. A catalogue not saved in Xcode's layout is refused rather than reformatted. `corpus init --messages App/Localizable.xcstrings` writes the source, reading the languages from the file.
- Under `library: "printf"`, a text may hold plurals on `argN` among its printf text, as a String Catalog's substitutions do: `{arg1, plural, one {%arg recent post} other {%arg recent posts}} from {arg2, plural, one {%arg participant} other {%arg participants}}`. Each plural is the Nth argument whatever a language names its substitutions, and `%arg`, or a branch's first verb with no index, is the argument itself. Such a plural is its argument's one slot, listed in argument order, and a preview picks its branch from that argument's example value. On Ice Cubes' catalogue this leaves 18 findings where the trial's converter run reported 60.
- A `gettext` source reads `.po` and `.pot` files with no converter: `{ adapter: "gettext", type: "ui", path: "locales/{lang}.po", sourcePath: "locales/app.pot" }`. Each msgid is a string keyed by its own text, a `msgctxt` joined before it, under `library: "printf"`. A plural is one ICU plural with a branch for each of the language's CLDR categories, read through the file's `Plural-Forms`. A fuzzy row is not seeded but sent as a suggestion, `seedSuggestions` in the snapshot (additive), which the editor offers above an untranslated draft and the string API and `get_string` return as a language's `suggestion`; `#.` comments and `#:` references are the note. `pull` writes a changed `msgstr` back in place, wrapped as msgmerge wraps it, clears `fuzzy` on a row it writes and appends an entry the file lacks; a missing `.po` starts from the template with every msgstr empty and its own language's `Plural-Forms`, compiled from CLDR's plural rules (`bin/gen-gettext-plurals`). On Joplin (43 languages, 1,854 msgids) it replaces a 272-line converter. `corpus init --messages locales/{lang}.po` writes the source, with the `.pot` as its `sourcePath` (GNU's `LC_MESSAGES` layout too).
- An `xliff` source reads XLIFF 1.2 and 2.0, Angular's i18n and most translation tools' export, with no converter: `{ adapter: "xliff", type: "ui", path: "src/locale/messages.{lang}.xlf", sourcePath: "src/locale/messages.xlf" }`. A unit's `<source>` is the string and its `<target>` a seed where its state is not `new`, `needs-translation` or `initial`; `<x>` and `<ph>` are placeholders, and `<g>`, `<pc>` and `<bpt>`/`<ept>` tags whose order and pairing are checked; a file whose elements carry a namespace prefix is refused by name. The note is the unit's description and meaning, then where Angular found the text (`Used in src/app/a.html:12 …`), as the gettext and qt-ts sources give theirs; the string page keeps a note's line breaks, so that line no longer runs into the comments. A placeholder's `equiv-text` is its example. `pull` writes a changed `<target>` with the unit's own inline elements, every other byte kept, and starts a missing file as the source file with `target-language` set. `corpus init --messages src/locale/messages.{lang}.xlf` writes the source, `sourcePath` included where Angular's `messages.xlf` sits beside the targets. On Ghostfolio (14 languages, 907 units) it replaces a 143-line converter.
- `library: "qt"`, Qt's `tr()` substitution: `%1` to `%99` and `%L1` are placeholders by number, in any order and repeated at will, `%n` is the numerus count, and any other `%`, braces and angle brackets are text unless the type is read as HTML. qBittorrent, through its converter, built only under `printf`, which read its `%1h %2m` time formats as verbs, 244 of 259 findings false in 51 languages, and missed its 72 real ones: `% 1`, `1%` and a dropped `%1` passed, while a correct `%1 ث` was refused as `Missing %1s`.
- `library: "rails"`, Rails I18n's and I18n.js's interpolation: `%{name}` and the format style `%<count>d` are placeholders a translation keeps as written, `%%` a literal, other braces text, and plural hashes read as one plural. No library read `%{name}`: under `icu` it was `%` and `{name}`, so a Discourse translation writing `{application_name}`, which Rails prints as it stands, was accepted, a refusal said `Missing {application_name}`, the chip inserted `{name}` without the `%`, and a literal brace was read as ICU. `corpus init` names it where `%{name}` placeholders dominate, and the plural chip fills each form with `%{count}`.
- `library: "easy_localization"`, the Flutter package's syntax: `{}` is a positional placeholder and `{name}` a named one, `@:key` and `@.upper:key` are links a translation keeps as written, and plural objects read as one plural whose `{}` is the count. AppFlowy's 56 English strings with `{}` were refused under `icu` and `vue` (`invalid placeholder name ""`) with no advice, so five of them did not stop the build, and under `i18next` or `printf` nothing was checked; its links were text, so a draft that dropped `@:appName` was accepted and 18 translations that write `@:appName-Konto`, a link to a key that does not exist, went unseen. They are now findings, a `{}` refused under another library advises this one, `corpus init` names it where strings with `{}` or links, counted, outnumber single-brace and ICU ones (a link counts only without vue-i18n's signs, since vue writes `@:key` too), and the plural chip fills each form with `{}`.
- `library: "counterpart"`, Element Web's matrix-web-i18n substitution: `%(name)s` and `%(name)d` are placeholders a translation must keep as written (`%(n)d` for the source's `%(n)s` is text in the app), a tag is a substitution, `<b>…</b>` or a bare `<pill>` with no close, and braces are text; its plural objects read as one plural. Under `icu`, `init`'s default, `%(count)s` was text: a Polish draft that dropped it was accepted and `validate` said nothing, over 608 of Element's 3,532 strings; three strings with a bare tag were refused. `corpus init` names the library when `%(name)s` outnumbers every other shape, and the editor's plural chip fills each form with `%(count)s`.
- An object of plural categories in a JSON catalogue, `{ "one": "…", "other": "…" }` as counterpart, easy_localization and Rails write a plural, is one string: an ICU plural on `count` under the `icu`, `i18next` and `printf` libraries. It was `key.one` and `key.other`, unrelated strings, so a form the source lacks was never seeded or shown and `validate` called 246 of Element's and AppFlowy's forms orphans. A pull writes the plural back as an object with the target language's forms in CLDR's order, bytes kept where nothing changed, and a translation the object cannot hold (an `=0` branch, a brace a form leaves open) is not written, which pull names. Under i18next a text that is one plural is read whole. **Upgrading:** such a key's `key.one` and `key.other` rows are archived by the first push and the key is one string, seeded from the repository's target files; drafts saved on the old rows stay in their history.
- The patterns of one source are one catalogue the application merges: an id two of its files hold with the same source text is one string: a pull writes its translation into each target file that already holds it, and into the first pattern's when none does, and a proposed edit or removal into each source file that holds it; two target files that translate it differently fail the build, naming both, since a pull could keep only one. Element Web merges its app's, desktop's and shared components' catalogues at runtime, and listing the three patterns failed on 61 duplicate ids with identical English; a `{ns}` pattern prefixed every id and translated the shared strings twice. An id with different text in two files is still a build error, now saying the text differs.
- The API's string response and `get_string` carry `forms`, how many vue-i18n pipe forms the source has (0 for any other string), additive: Hoppscotch's `{count} script | {count} scripts` read as `placeholders: ["count"], plurals: []`, and an agent learnt it had two forms only by reading the text.
- An `exec` import command can say what it changed: `{"changed": [paths]}` as the last line of its stdout is counted in `pull`'s summary, where Joplin's `de_DE.po: 5 entries written` was followed by `0 file(s) changed`. An exec source that declares `importCheck: true` has its import command run by `pull --check` with `CORPUS_PULL_CHECK=1` in the environment, to report and not write, and its files counted toward the check, where a check skipped exec sources and was no gate for them; without the declaration a check still runs no import command. `build` and `push` print an export command's stderr under `exec "<command>":` (Joplin's converter reports fuzzy and skipped entries there), and say how many of the translations it handed over were not seeded, for an id it did not emit, a string refused or an empty text: Discourse's exporter emitted 252,417 and push accounted for six fewer, with no line why.
- A translation identical to its source can be seeded as translated. An exporter marks one so, `{ "text": "Status", "state": "translated" }` (the snapshot's `seedTranslated`, additive): Ghostfolio's 57 German loanwords, `Name`, `Status`, `Portfolio`, sat in the untranslated queue as work. A config may declare `sourceVariants: ["en-GB", "en-AU"]`, target languages that are variants of the source: their identical seeds are translated and their untranslated rows are left out of the untranslated queue, as the application falls back to the source for them (qBittorrent's en_GB had 2,350 of 2,502 rows untranslated, Joplin's en_US 1,800). The instance keeps the list (migration 0020), replaced by each push, and either change resends that language's seeds; the migration forgets the seed digests, so the first push after upgrading resends every language's.
- A `messages` or `fluent` source may map a language to the code its files use, `languageFiles: { "zh-CN": "cn", "sr-Latn": "sr@latin" }`: the project's language is the tag, with its plural rules and display name, and push, validate and pull read and write the file under its own name. Hoppscotch keeps Simplified Chinese in `cn.json`, and had to declare `cn`, which no runtime knows; qBittorrent keeps Serbian (Latin) in `sr@latin.ts`, which no config could declare.
- A translation a push seeds from the repository that fails validation is kept and marked **invalid**, where it used to count as done: Hoppscotch's `af` `"Join {team}"`, left behind when the source moved to `{workspace}`, was one of 130 such seeds, and a team saw German 942/2140 translated with no way to find its broken 6 but `corpus validate` offline. The dashboard and a project's card list an **Invalid** queue once a project has any, the dashboard counts them beside each language's and type's progress, `corpus status` and `/api/status` count them per language and type (a new `invalid` column), and `/api/queues`, `list_queue` and `corpus agent queue invalid` list them, each item with its `problem` as the editor says it; `get_string` carries `invalid` and `problem` per language. A save clears the mark, and so does a push whose text passes; a push that changes a string's source, library, `arguments` or its type's `richText` reads again every translation of it no one has saved in Corpus, marking or clearing it, though the seed digest leaves the unchanged seeds out of the push; a verify changes neither. A translation that is its source's own text is never marked, as its source is only warned. An agent may redraft an invalid row, as it may a stale one. The instance keeps the mark (migration 0019), and the migration forgets the seed digests (#601), so the first push after upgrading resends every language's seeds and marks the ones the instance already holds. A first push checks every seed, about half a second on Bitwarden's 546k.
- `corpus push` asks the server which adapters and libraries it accepts (`/api/health` reports them as `accepts`) and refuses, naming them, a project whose sources a server that predates them would refuse: `the server at … predates the yaml adapter this project uses; upgrade it to 0.21.0 (@corpus-tool/workbench or the image), then push again`. A server that reports none is older than 0.21.0 and is checked against 0.20.0's, and its refusal of a push draws the same advice. **Upgrading:** upgrade the server, the workbench package or the image, with the CLI. A 0.20 server silently ignores `sourceVariants`, `seedTranslated`, `seedSuggestions` and a string's `arguments`, so a 0.21 push to it seeds and validates as 0.20 did.

### Changed

- `corpus init` writes the string type `ui` when `--type` is not given, where it wrote `chrome`, which since 0.20.0 read like the `chrome` library (Chrome i18n): agents on Joplin, qBittorrent and Ghostfolio took it for a misdetected library. A config that names `chrome` keeps it.

### Fixed

- A push that carries no examples for a string clears the ones it had. They stayed, so the editor previewed, and `get_string` returned, values for placeholders the text no longer had.
- Under `printf`, a string's slots and the editor's placeholder chips read in argument order: `%2$s wrote %1$d` listed them as 2 then 1.
- A string with a plural and a select on one argument, `{n, plural, …} {n, select, …}`, offered one chip that inserted the select's keys into the plural (`{n, plural, one {#} other {#} a {#}}`), which validation refuses; each now has its own chip.
- In a type declared `richText: "html"`, a tag that never closes, or a stray closing tag, is text, as a browser reads it: Discourse's "HTML to insert at the end of the `<head>`" and an unclosed `<p>` no longer stop a build, and its client catalogues build (7,985 strings; the 3 `_MF` strings that nest a plural in a select wait for #674). A component-rendered type still refuses an unclosed tag.
- In a type declared `richText: "html"`, a placeholder inside a tag's attribute, `<a href='%{topicUrl}'>` under `rails` or `<a href='{url}'>` under ICU, must be kept, as the text's own placeholders are, whether the tag closes or not. Such a type does not compare its tags, so Discourse's `user_posted_topic` counted `%{user}` only: a draft cut short of its second link was accepted, and so was an Arabic translation linking to a `{groupName}` its message is never given.
- Under `rails`, a `%{` that opens no placeholder, `%{dana]`, `%{{username}` or a name with spaces, is refused: Rails prints it as written. `validate` finds 35 on Discourse, 33 of them Swahili translations that translated the placeholder's name.
- Outside ICU, a translation whose every form leaves out the count the source prints is refused. The plural on `count` it still carried counted as keeping it, though under counterpart, Rails and i18next a plural prints nothing: an Element Polish draft with no `%(count)s` in any form was accepted. Discourse's Hebrew `collapsed_replies`, `posts_count` and `error_topic_count` say "two" in their `other` form, whatever the count; `validate` now names them.
- A target file's plural object or Rails hash without `other`, at a key the source reads as a plural, is that plural. Element's Polish `{ "one", "few", "many" }` (97 objects, and 89 more in uk, ru, he, tr, is and lt) was read as three keys the source no longer has: `validate` named 291 orphans, a push never seeded them, and a draft replaced the file's forms unseen. They seed now, a pull leaves them as they are, and `validate` names each for the `other` it lacks, which counterpart falls back to for every count but 1.
- Under `counterpart` and `easy_localization` a plural's branches are checked by the library's own rule, not CLDR's. counterpart picks by English's in every language, and easy_localization by the value (0, 1 and 2 read `zero`, `one` and `two`), so a Polish `few` is dead text in both, and a Japanese counterpart plural needs `one`, without which Element shows the English string for one item. Element's 1,540 plural warnings become 400 and AppFlowy's 517 become 227, each one what the runtime does; the editor's plural chip offers the same branches.
- A gettext plural's branches are the ones its target file's `Plural-Forms` picks. Real `.po` files give Italian, French, Spanish, Portuguese and Catalan `nplurals=2`, where current CLDR adds `many`, so the editor's chip inserted a `many` the file cannot hold and an agent's Italian draft was told it lacked one. A push carries each plural string's categories per language where they differ from CLDR's (Joplin: 28 strings, 11 languages), and the editor and drafts ask for those; a seeded plural shows only the forms its file holds, so an edit to a French `many` alone, which the file had no place for, is no longer silently dropped.
- `corpus init` writes `richText: { <type>: "html" }` for a Rails yaml catalogue whose source holds tags only HTML reads, an unclosed `<p>` or a lone `<br>`, and names the line for any other library; `corpus build` names it once per type beside such refusals. Discourse's config as init wrote it refused 13 strings and built nothing; it builds its 7,988 now.
- A source with a list of patterns may say `merge: "last-wins"`, for an app that merges its catalogues in order with the later file overriding the earlier: the later file's source text and translation are the ones read, a disagreement is a build note and a `validate` warning rather than a build error, and a pull writes into the last file that holds a string and into an earlier one only where it agreed, so push∘pull still round-trips. Element Web's app and shared-components catalogues, whose 92 translations in 16 languages disagree, build with it (3,673 strings) and pull back byte-identical; `"strict"`, the default, keeps the rule that refused them.
- `validate` names an orphan key where it is, the target file that keeps it, with the source that no longer has it in brackets and how many other target files carry it, where it named the source file.
- A config language that is not a tag is refused by name, `"sr@latin" is not a language tag; write sr-Latn, and map its files with languageFiles: …`, where it said `languages.2: a language tag such as en, pt-PT or en_US`. `corpus init` no longer warns for a real language the runtime has no plural rules for, `kaa`, `oc`, `oc-FR`, `ltg`, when it has a name for it; it still warns for a made-up code and for Crowdin's `cr` and `ach`.
- `corpus check` skips test, spec and story files (`*.test.*`, `*.spec.*`, `*.stories.*`, anything under `__tests__/`) and says how many: 7 of Excalidraw's 33 findings were `*.test.tsx` fixtures. A `__tests__` directory named in `check.include` is read. A JSX text shorter than its indentation is reported at the line it is on, where it was counted from past its own leading whitespace and named the next line (Excalidraw's `TTDDialogOutput.tsx:70` for `Likely causes:` on 69).
- `corpus init` finds a monorepo's components: where no top-level `src`, `app`, `lib`, `components` or `shared` holds any, it writes the `components` directories to four levels down, Hoppscotch's `packages/hoppscotch-common/src/components`, or else the roots of the catalogue's own package, and says when it found none. Five of the nine trial projects (Excalidraw, Element Web, Hoppscotch, AppFlowy, Ice Cubes) got no `check` block and a first `corpus check` that scanned nothing. That message, `set check.include in …`, names the config file the repository has, where it said `corpus.config.ts` to a repository whose file `init` had written as `corpus.config.mjs`.
- A pull writes a key new to a target JSON file where the source-language file has it, after the nearest key before it that the target holds, where it went last in its object, and a missing object at its source position, where it went last in the file (Hoppscotch's `de.json` got its `script` object at the end). Catalogues whose target files mirror the source's order, kept so by Crowdin, Weblate or matrix-sort-i18n, as Excalidraw's, Hoppscotch's, AppFlowy's and Element Web's are, were reordered by the project's next sync; unchanged rows keep their bytes as before.
- A placeholder name in any script is a placeholder, so a translated name reads as what it is: AppFlowy's Thai `{เวลา}` for `{time}` was `invalid placeholder name "เวลา"` at a position, where the same mistake in German reads `missing {time}; unexpected {Zeit}`, and so were Hoppscotch's `{名前}` and `{наме}`. It now reads `missing {time}`, `unexpected {เวลา}`, under ICU, vue-i18n and i18next alike, and `init` counts such a name when it guesses the library.
- Under `library: "printf"` a text that is wholly one ICU plural, `{count, plural, one {%d card} other {%d cards}}`, is read as that plural: the verbs of each branch are counted from 1 and checked as an Android `<item>`'s are, and the plural's categories as ICU's. A converter from gettext plurals or a String Catalog's plural variations had to choose `printf`, reading the plural as text (77 bogus findings on Ice Cubes), or `icu`, reading the verbs as prose, which let a Joplin draft `{count, plural, one {Karte} other {Karten %s %x}}` through. `#` and angle brackets stay text under printf; a printf text that does not parse as exactly one plural, with text after it, a brace inside a branch or no `other`, is read as before, so nothing that pushed is refused. A plural read whole on a named count previews from argument 1 when an example gives no `count`: `{1: 1}` rendered `1 cards` and now renders `1 card`.
- A plural branch the language never selects is incomplete, a warning `validate` lists apart, where it was invalid and exit 1: Ice Cubes' Japanese, Korean and Chinese `one` branches are dead text Foundation never picks, and Discourse's Hebrew `many`, which its ruby-cldr keeps and Node's CLDR dropped, could not be fixed either way. A language whose only category is `other` may write a plural as the plain text of its `other` branch, keeping that branch's values (`#` as the count): Ice Cubes' `{count}件` for a `{count, plural, …}` source was refused. Not under Android, where a `<string>` is a resource the code's `getQuantityString` never reads. A push no longer marks such seeds invalid.
- A plural whose `=1` branch is the whole of its language's `one` is complete: Ghostfolio's Angular `{VAR_PLURAL, plural, =1 {Profil} other {Profile}}` was told it lacks the `one` branch in German, Dutch, Spanish, Italian, Catalan and Turkish, 18 of its 24 incomplete findings. - `corpus workbench` and `corpus init` leave `.gitignore` alone when git already ignores `.corpus/`, by a parent directory's `.gitignore`, `.git/info/exclude` or a global excludes file: they appended the line anyway, so every trial's tree showed `.gitignore` modified after the first `corpus workbench`, and Ice Cubes' round-trip check with it. Outside a git work tree, or without git, the line is written as before. `.git/info/exclude` and a global excludes file hold for one clone only: where others will paste a token into `.corpus/`, the tracked `.gitignore` should name it.
- A key or id with a newline or another control character prints escaped (`\n`, `\t`, `\u001b`) in `validate`'s findings, `build`'s refusals and `pull`'s notes, so each stays one line: Joplin's gettext msgids, which are its ids, span lines, and a finding naming one ran onto the next two lines, where CI that reads one finding per line misread it. `validate --json` keeps the raw string.
- A catalogue no adapter reads is refused by its format: `corpus init --messages "config/locales/client.{lang}.yml"` wrote a config for Discourse's YAML and `build` then failed with Node's `Unknown file extension ".yml"`, and qBittorrent's Qt Linguist `.ts` was read as TypeScript (`ParseError: Unexpected token`). `init`, `build` and `validate` now say `a YAML catalogue, which no adapter reads: an exec source converts it`, and name gettext, XLIFF, a String Catalog, Apple `.strings`, Java `.properties` and `.resx` the same way; a `.ts` that opens with `<?xml` or `<TS` is Qt Linguist, and a `.ftl` or an Android `strings.xml` names the adapter that reads it. `init` writes no config for one. A TypeScript or JavaScript catalogue reads as before.
- printf's hint for a moved verb follows the source: `%n$` where the source writes one, Go's `%[n]` where it writes that, and both (`%n$s or %[n]s`) where it writes neither. It offered Go's `%[n]` to every source without a `%n$`, and Joplin's JavaScript sprintf throws on it. A verb whose type changed where it stands (`%d` against `%lld`, `%i` against `%s`) is said as a changed type, with no index hint: nothing moved. The finding carries `moved` (additive).
- Under `library: "vue"` angle brackets are text, as vue-i18n has no tag syntax: Hoppscotch's `Replace <access token> with your token` was refused as an unclosed `<access>` in `validate` and in every draft, and no `richText` setting helped. Until that push, a translation of such a string already on the instance is refused on save. The editor's chip and the proposal form follow the same rule.
- A pull writes a key new to a target file under the key path the source file gives it, so a segment that holds dots stays one segment: Element Web's `"m.room.topic": { "removed": … }` took a new translation as `"m": { "room": { "topic": … } }`, where its i18n never looks, and the app showed English. A proposal edits and removes such a key where it is. Two key paths that flatten to the same id (`"a.b": { "c" }` and `"a": { "b.c" }`) are refused at build, naming both; a target file that already holds such a misplaced subtree from an earlier pull is named by that error, and removing the subtree fixes it.
- An id, a select value or a branch key named like a member of `Object.prototype` is an ordinary name. A pull writing a JSON catalogue wrote an id such as `toString` as `"toString": undefined`, which is not JSON, or wrote a table row without its text. A preview threw on a select value such as `constructor`, and validation dropped a `__proto__` branch, so a translation that left it out passed. An example value for a placeholder named `__proto__`, pushed or read from a Chrome catalogue, reaches the server, where parsing dropped it, and a Chrome placeholder `$CONSTRUCTOR$` with no example stays as written, where the example rendered it as `Object`'s source. A JSON catalogue key named `constructor` or `__proto__` is still refused by name, and a `__proto__` example value that is not a string is refused as any key's is, where parsing dropped it without a word.
- A target file that a pull starts from the source-language file, a new ARB file or an empty one, keeps that file's line endings and byte-order mark.
- A pull that rewrites a `table` file keeps its line endings and byte-order mark, so a pull that changes nothing leaves a CRLF or BOM table byte for byte, where it wrote LF and dropped the BOM. A blank table file starts from the source-language file's layout, as a blank messages file does; a table with no records is written `[]`, left as it is when nothing goes into it, and takes the source file's layout once something does.
- A row a push resets to untranslated is no longer stale: a seed identical to its source, after the source changed and changed back, left the row untranslated and in the stale queue. Migration 0024 clears the rows earlier pushes left so.
- A preview reads a date given as digits as epoch milliseconds, as FormatJS does. It showed `1700000000000` as those digits, and read `5` as a date in 2001. Under i18next, a value the example lacks shows in i18next's form, `{{name}}` (or `{{- name}}`, and `{{count}}` for a source's `{{ count }}`), not ICU's `{name}`. A plural whose count is empty takes its `other` branch, where it read the empty count as 0 (Russian previewed `many`).
- A config is refused, by name, where it writes `{ns}` in the path of an adapter that does not read it (`android does not read {ns}: only messages, table and fluent do`) or a library field the build does not read (`android sets its own library; library does not apply`, and on an exec source `an exec source's entries carry their own library`). Both were ignored.
- `corpus init` reads a catalogue named with a POSIX modifier, `sr@latin.json`, as its language, mapped through `languageFiles`, and says plainly when the source language's file is missing; `build` says `source file … does not exist` there, where it printed Node's `ENOENT`. A pattern that writes `{lang}` twice reads one code from both places. A JSON catalogue whose name carries a POSIX modifier that is no tag, `ca@valencia.json`, is said to name no language, to be mapped with `languageFiles`, where it was called a sibling catalogue a `{ns}` pattern would name. `build`, when it refuses a string it cannot read, says no snapshot was built, where it said nothing was pushed.
- The ICU parser is bounded on hostile input. Nesting past 200 levels is refused, a regex that could backtrack is gone, and vue-i18n's pipe forms are split in linear time, so no message, pushed or drafted, can stall the CLI or the server: `"{{".repeat(20000)` under vue took 3 s.

## [0.20.0] - 2026-09-27

The formats projects have, and what 0.19.0 left: Chrome i18n, Android string resources and Fluent read natively, a string type read as HTML, and a large project that pushes in seconds and answers status and queues at once.

### Added

- A string type may be declared as read by an HTML renderer, `richText: { ui: "html" }` in the config: its translations' tags are not compared with the source's, so a translation may write `<i>` or `<br/>` the source lacks, while placeholders, plurals and selects are checked as before and an unclosed tag is still refused. `corpus validate`, the editor, a save and an agent draft all read it; the snapshot carries the map (additive, still `corpus/1`), the instance keeps it (migration 0017) and a push replaces it whole; the string page says the type is read as HTML, and the API's string and `get_string` carry `richText`. AntennaPod's Breton and Korean translations of a string Android shows through `fromHtml` drew four findings for tags that render correctly.
- Chrome i18n's `messages.json`, the catalogue of every browser extension, is a `messages` format under `library: "chrome"`: the adapter reads an object of `{ message, description?, placeholders? }` entries as Chrome does, `message` as the text, `description` as the note and each placeholder's `example` as its example value, and a pull writes the `message` back in place, keeping the rest of the entry and a byte-order mark, a key new to a language copying the source's `description` and `placeholders`. `$NAME$` is a placeholder, matched without regard to case as Chrome matches it, and `$$` a dollar; `init` names the library from the shape; without it the shape reads as nesting, as before. Bitwarden's four apps, 8,617 strings in 67 languages, push through two `{ns}` patterns with no converter and pull back byte-identical; in the 0.18.0 trial they took a converter that rewrote `$NAME$` to `{NAME}` and back.
- Android string resources are a source: `{ adapter: "android", type, path: "<res directory>" }` reads `values/strings.xml` and each config language's `values-<qualifier>/strings.xml` by Android's rule (`pt-BR` is `values-pt-rBR`, `sr-Latn` is `values-b+sr+Latn`), a `<plurals>` as one string with an ICU plural on `quantity`, and skips `translatable="false"`, product variants and `@string/` references. The text is what the app shows, escapes, entities, CDATA and quoted whitespace undone, and a pull writes it back escaped, editing only the elements that changed and appending new ones before `</resources>`, so an unchanged file is byte-identical, comments included. The entries carry the new `android` library: printf verbs (the index form offered is `%n$s`) and tags, each plural item counting its verbs from 1 and a verb changed in any item named. AntennaPod's 840 strings in 52 languages push with no converter and pull back unchanged; `validate` names its four HTML tags in Breton and Korean, four `<plurals>` that Simplified Chinese writes as `<string>`, and a Czech `&lt;br&gt;` shown as text. `corpus pull` now creates a target file's directory when the language is new to the repository.
- Fluent `.ftl` catalogues are a source: `{ adapter: "fluent", type, path: "i18n/{lang}/app.ftl" }` reads messages with a value as ICU, `{$var}` and message references as placeholders and a select on a variable as a plural (or a select, for keys that are not plural categories), and refuses attributes, terms, functions and string literals by name. A pull rewrites a changed message in its own layout and appends new ones, so an unchanged file is byte-identical, comments included. cosmic-files' 247 messages in 75 languages push with no converter and pull back unchanged; a plural draft comes back as a select block in the file's layout, and `validate` names the Galician selects that pick a count by `[unha]` and on a variable the translator renamed.

### Fixed

- Status and the queues answer quickly on a large project: the progress numbers are counted in SQL over a new `(language, state, stale, string_id)` index (migration 0018, which replaces the `state` index), and each queue is a condition in SQL with the API's `?language=` and `?type=` applied there, where every translation row used to be loaded and filtered in the server. On Bitwarden's 586k rows `GET /api/status` takes 0.13 s (1.1 s) and `GET /api/queues?language=de` 0.01 s (2.6 s); the dashboard reads each queue's count and first item. The index costs a first push of that size about half a second (10.0 s).
- A first push is quicker: new strings and their translation rows go in batches of statements prepared once, a string's seeds are written into the rows that create it instead of in an update of every row afterwards, and the check for rows a language added in settings lacks runs before the new strings rather than over them. Bitwarden's first push, 8,617 strings with 316,203 seeds in 67 languages, takes 9.4 s from the command line where it took 20 s after the memory fix below (80 s before it); an unchanged push is as it was, and the report is identical.
- A config that writes `pt-PT` over a Flutter project whose files follow gen-l10n's own naming, `strings_pt_PT.arb`, is refused when it loads, naming the code to write (`pt_PT`). A first pull used to create a second file, `strings_pt-PT.arb`, beside the real one, which gen-l10n then refuses as two files for one locale, and push seeded nothing from the real one.
- A new string proposed into a namespaced file (a `{ns}` pattern's `admin.json`) takes the file's prefix, `title` becoming `admin:title`, whether it comes from the workbench's form, which now says which prefix each file adds, or from an agent. It used to be created under the bare key, which `pull` refused and the next push never matched, so it stayed pending for good. A writable source carries its `namespace` (additive, still `corpus/1`).
- A large push no longer leaves the instance holding gigabytes: every seed and every string was written through a statement prepared for it alone, and SQLite's native memory for those statements was never returned to the system, so Bitwarden's first push (316,203 seeds, 586k rows) left the instance at 2.8 GB resident, 3.7 GB as the push returned. Each write is now prepared once per push, and the seeds are compared one language at a time: the same push returns at 340 MiB, settles near 160 MiB, and takes 20 s where it took 80. The report is unchanged; the wiki's *A team instance* says what memory a project that size needs.
- A changed source marks stale its `translated` and `verified` rows only; an untranslated row has nothing to go stale and is left alone, where every target row of a moved source used to join the stale queue whether anyone had translated it or not. A source whose text was the empty string takes its text with no stale mark, and `corpus push` says so (`578 source(s) took their text where it was empty, nothing marked stale`): the first 0.19.0 push of a key-is-text catalogue (Ghost) changed 578 sources from `""` to their keys and marked all 35,898 of their rows stale, 22,564 translated ones included, which also opened every seeded translation to agent drafts.
- A proposal on a string whose text is its key is refused with the reason: "the text of `<key>` is its key: change it in the code that calls t(), and the catalogue follows", on the API, through the MCP `propose_change` and `propose_removal` tools, from `corpus agent propose`, and on the string page in place of the proposal buttons. It used to say the string came from a source pull cannot write, and list the writable sources, the string's own among them. The snapshot entry carries `keyIsText` (additive, still `corpus/1`), the instance keeps it (migration 0016; an older CLI's push leaves it false), and `get_string` carries it so an agent knows before it tries. A proposal on an exec or `.ts` string keeps its message.
- Under the `printf` library a verb carries C's length modifier, `%ld`, `%lu`, `%zu`, `%lld`, `%hhd`, as one verb, and `%@`, Objective-C's object verb, is a verb: `%ld` used to be read as `%l` followed by `d`, so the chip inserted `%l`, a dropped one was `missing %l`, `%ld` against `%lu` passed, and an iOS `.strings` catalogue got no check on `%@`. A changed verb compares the modifier and the letter together, and the index form names both (`%[n]lu`). A translation that drops the middle verb of `%s pushed %d commits to %s` is told `missing %d` once, where it was told the second verb changed and the third was missing. Java's `%,d` and Go's `%[2]*d` are as they were, and the wiki says so.
- A first pull into a missing `.arb` writes `@@locale` in the underscore form, `pt_PT` for a config's `pt-PT`: Flutter's `gen-l10n` normalises the locale it parses from the file name to underscores and compares `@@locale` with it as written, so the hyphenated code it got on 0.18.0 failed the build with "do not match" where a file without the key had passed. A code the config writes with underscores is written as it is.
- The wiki's version strings cannot lag a release: the `/api/health` answer on *A team instance* is recorded by `bin/wiki-record-live` (it said `v0.16.0` by hand, two releases behind), and the wiki test asserts that every version in the recorded sessions and the health answer equals `packages/cli/package.json`'s, so a release branch's gate fails until the recordings are re-taken. The MCP and agent recordings are re-taken here, and now carry `keyIsText` and fresh timestamps.

## [0.19.0] - 2026-09-23

What the 0.18.0 trial found: the door (empty i18next sources, HTML with attributes, printf verbs, the config init writes) and the size (a 128 MiB push, seeds sent once, a gzipped pull).

### Added

- A pull's payload is gzipped from 256 KiB when the client accepts it, which Node's fetch does on its own: Bitwarden's pull at `translated` was 7.5 MB on the wire on 0.18.0 and is about a megabyte now; a small project's pull stays plain.
- A push leaves out the seeds the instance already holds: the snapshot carries a digest per target language of the repository's translations, the instance keeps the last push's and `GET /api/status` returns them, and `corpus push` asks first and sends only the languages whose digest moved, saying `seeds unchanged for 55 language(s)`. Every push used to carry the whole catalogue, 48 MiB for Bitwarden on each CI commit, for the server to parse and compare away; a first push, a moved file, and an older instance still get everything.
- A `printf` library: under `library: "printf"` a verb is the placeholder, `%s`, `%d`, `%-8.2f`, Go's `%[2]s` and C's `%2$s`, named by its position as Go reads it, `%%` a percent and a stray `%` text, with braces and angle brackets as text. The cap bounds the body; a push at that size costs several times it in memory while it runs (#604).
- A rich-text tag may carry attributes, `<a href="%s" target="_blank">…</a>` or `<code id="branch_target">…</code>`, kept as part of the tag's identity: a translation must carry the same attribute text verbatim (a changed `href` is a missing tag and an unexpected one), the editor's chip inserts the tag whole, and `br`, `hr`, `wbr` and `img` are void, so `<br>` needs no close and `</br>` is refused. Gitea's 4,000 strings had 92 refused for `<a href>`, `<strong class>` and a lone `<br>`, at or past the five that stop a build; they build with none. The API's `tags` and the MCP `get_string` carry the attribute text with the name.
- An empty value under a sentence key reads the key as the source text: an i18next catalogue with natural keys (Ghost) writes the sentence as the key and `""` as the value, and Corpus used to push 579 of 588 strings with an empty source, mark 6,892 seeded translations invalid for a placeholder the empty source did not declare, and refuse every draft. A dotted key with an empty value stays empty.
- `corpus pull` prints what an import command wrote to stderr under its `ran` line and counts the commands in its summary (`0 file(s) changed, 1 import command(s) ran`); it used to print `0 file(s) changed` after an importer had written a file, since the count is the adapters' alone, and swallowed the importer's own account when it exited 0.
- A `corpus validate` finding names its language: every `--json` row carries `language` (a source's own finding carries the source language), and a finding on an `exec` source prints it after the key, `exec:<command> [key] fr: missing {trash}`, where the command stood for every language at once; a file source's line is unchanged, since its path names the language. On cosmic-files 129 lines over 74 languages said nothing about which.
- `corpus init` counts the placeholder shapes a catalogue uses before naming its library: `{{ }}` is i18next only when it outnumbers the single-brace and the printf strings, so Gitea's one `{{filesize}}` among 4,000 printf strings no longer makes the project i18next; a catalogue whose placeholders are mostly printf verbs is named `printf`, and i18next plural keys with `{ }` interpolation (Ghost) are told they stay `icu`, which checks the placeholders where the i18next library would read a single brace as text.
- `corpus init` writes `corpus.config.mjs` as a plain object when `@corpus-tool/cli` is not installed in the repository, and says so; it used to write the typed `corpus.config.ts`, whose import of the package fails to load on the next command when the CLI runs from npx (every project of the 0.18.0 trial). With the package installed it still writes the typed file.

- `corpus pull` says what applies a proposal it wrote: commit and push, and the next `corpus push` marks it applied. The MCP instructions and the README say the same.
- A tool or stdin argument given as a number is taken as its digits, so an id read from `list_proposals` goes straight back in.

## [0.10.0] - 2026-09-17

What the second MCP run found.

### Added

- `corpus agent --stdin` (§3): many operations through one process, one JSON object per line in (`op` is `queue`, `string`, `draft`, `propose`, `remove`, `add` or `status`) and one JSON line per operation out, in order, with the server's error and message on a refusal, `unreachable` when the server is down, and an echoed `id`; no start-up per call and no shell quoting around a translation.
- The string response and `get_string` carry the entities a string refers to, as the editor's cards show them: field, id, type and its label, name, attributes. The contract gains `entities`; still `corpus/1`.

### Changed

- The README leads with the agent surface and no longer carries a status paragraph.

### Fixed

- A pull or a proposal edits a messages file in place (§8): a changed value replaces its token, a removed key goes with its comma and the object it empties, an added key lands in its object's own style, inline or expanded, with the file's line ending; every other byte stays. A catalogue that keeps small objects on one line was rewritten whole before, so three proposals read as a hundred changed lines.
- The CLI exits only once its output has drained, so a long answer through a pipe keeps its tail, and a reader that closed early (`| head`) ends it quietly instead of with a stack trace.

## [0.9.0] - 2026-09-16

What the first MCP user found.

### Added

- **Siblings** (§9.3): the other strings of the same type under the same key prefix, the ten nearest in key order with the total, under the source on the string page and on the string response and `get_string` with every target language's text and state, so a set of quips or a run of steps is translated as one.
- **A voice note per string type** (§5): `typeNotes` in the config, one sentence per type on voice and register, pushed with the declarations and shown under the source and in `get_string`.
- **A glossary** (§5): `glossary: { path }` in the config names one JSON file per target language of `{ term, target, note? }` entries the repository owns; `corpus build` reads every target's file and a push replaces the project's copy whole. The string page and `get_string` show the entries whose term occurs in the source, matched on whole words case- and accent-insensitively. Not enforced.
- **`corpus agent`** (§3): the seven MCP tools as subcommands (`queue`, `string`, `draft`, `propose`, `add`, `status`), each printing the API's JSON, for an agent that has a shell and no MCP client.
- Queue items carry the string's `type`; `GET /api/queues` and `list_queue` narrow by type as well as language.
- `GET /api/status` and `corpus status` carry the project's writable sources, and say when the last push predates their declaration.
- The snapshot carries `typeNotes` and `glossary`, the string response carries `note`, `glossary` and `siblings`, and queue items carry `type`. All optional; the contract stays `corpus/1`.

### Changed

- A refusal says what to do next: `409 human-edited` names the agent's move, and `not-writable` / `unknown-source` end with the writable sources, "no writable source", or "last pushed before sources were declared; run corpus push with this CLI".
- The CLI always sends `sources`, empty included, so a project with nothing writable is told so rather than asked to push again.
- README: connect the MCP server before the session starts, match the instance's version, push once after upgrading, and how to drive the server as a subprocess.

## [0.8.0] - 2026-09-15

Agents draft; people verify.

### Added

- The project token reads and drafts (§10): `GET /api/queues`, `GET /api/strings/<key>`, `PUT /api/strings/<key>/translations/<lang>`, `POST /api/strings/<key>/proposals` and `POST /api/proposals`, under three rules. An agent never overwrites a person's current work: a draft lands on an untranslated row, a stale row or the agent's own earlier draft, and a row a person edited (or push seeded) answers `409 human-edited`. Every draft is attributed to the project's agent actor, `<slug> agent`, a user that never signs in, shown as such in the history, the chips and the settings list. Nothing but a signed-in maintainer verifies: the token has no verify route.
- A fourth queue, **agent drafts**, on the dashboard and the home card once the project has any: the translated rows the agent last edited, for a maintainer to walk and verify.
- `corpus mcp` starts a Model Context Protocol server on stdio from the repository, reading the config and the token like every other command, with seven tools that are one API call each: `list_queue`, `get_string`, `save_draft`, `propose_change`, `propose_removal`, `add_string` and `status`. Refusals come back as tool errors with the server's message. The README says how to connect Claude Code or any MCP client. Corpus runs no model; the model stays on the agent's side.
- The contract carries the agent surface's bodies and responses; still `corpus/1`.

### Changed

- A language bar at the top of the string page, inside the queue bar on a desktop, is the editor's switcher: one segment per language, the selected one solid, the source language first with its verified mark. The state chips are display only.
- The join form refuses any name ending in ` agent`, the name family reserved for agent actors.

## [0.7.0] - 2026-09-15

Corpus proposes source strings.

### Added

- Anyone on the instance may propose a change to a string's source text, its removal, or a new string into a catalogue chosen among the sources push declared (§9, §11). A proposal is pending until `corpus pull` writes it into the source file and the next `corpus push` sees the repository agreeing; a push that moved on, or archived the string, marks it superseded. One proposal per string or key; a newer one replaces the older, and every outcome reads in the string's history.
- `corpus pull` writes pending proposals into the source-language files through the adapters, format preserved, and removes a deleted key from the source's target files too; `--check` counts them; `corpus status` shows the pending count. A pull with no pending proposals never writes a source file.
- The snapshot carries each entry's `file` and the writable `sources`; the pull payload carries `sourceChanges`. All optional; the contract stays `corpus/1`.
- Strings from `exec` sources, or from `.ts`/`.js` catalogues pull cannot write, refuse proposals with a reason.

## [0.6.0] - 2026-09-07

The editor speaks the target language.

### Added

- Examples may carry `valuesByLanguage`, slot values resolved per target language by the client's exporter; the contract stays `corpus/1`. The editor previews a draft with the selected language's values when the example has them, and says which language the preview is in; a placeholder chip's hover shows the slot's description and, when the example has a value for the language, what it resolves to.
- The editor's language chips switch the target language on the string itself, keeping the queue when the switched-to row is in it.
- The other languages of a string are readable under the source while translating: current text, state, stale marked. Read only; editing stays one target at a time.
- The Moonlight Manor fixture carries English example values, so the smoke and the screenshots show an English draft previewing as the English sentence.

## [0.5.0] - 2026-09-07

The CLI covers the headless path: what the first outside integration asked for, ranked by how often it was blocked.

### Added

- `corpus workbench` creates the project `corpus.config.ts` declares when it starts in a repository with no `.corpus/token`, and writes the token there (owner-only); an existing project is named with its settings page. `--no-provision` opts out.
- `corpus project create [--name] [--server]` creates the config's project on any instance with the instance secret (`CORPUS_INVITE_SECRET`, or `.corpus/secret` for a local workbench) and prints the token alone on the last line of stdout; `corpus project rotate-token` replaces a token with the current one and rewrites `.corpus/token` when that is where it came from. Server side: `POST /api/projects` with the secret, rate-limited like the join form, and `POST /api/projects/<slug>/token` with the current token.
- Where a command needs the project token it reads `CORPUS_TOKEN`, then `.corpus/token`.
- `corpus status [--json]`: the dashboard's numbers in the terminal, per language and per string type, with the string count, the last push and the server's version, and a line naming any language the config and the project disagree on. `GET /api/status` with the project token.
- `corpus pull --lang <l>` (repeatable) pulls one language's files and leaves the rest alone (`/api/pull?lang=`); `corpus pull --check` writes nothing and exits 1 when a pull would change a file.
- `corpus validate [--json]`: the editor's checks over the target files of every JSON source, offline: a dropped placeholder, a malformed select, or a key the source no longer has is a finding, `file:key: message` one per line, exit 1. The repository's own gate runs it.
- `corpus push` names languages the config declares that the project lacks, and the reverse.

### Changed

- The gate scripts (`bin/dogfood`, `bin/install-smoke`, the screenshot fixture) create their projects through the CLI and the API instead of inserting rows by hand.
- The README's quick start is `init`, `workbench`, `push`; a section on CI gates; the screenshots are retaken at a smaller desktop viewport with a staged project that shows every state.

## [0.1.0] - 2026-09-05

The first published version.

### Added

- `corpus init` writes a `corpus.config.ts` from flags and prints the next steps.
- `corpus push` diffs a repository's text into a Corpus instance by string id: adds, changes (marking translations stale), archives.
- `corpus pull [--min-state <state>]` writes translations back through the same adapters, format-preserving; push then pull reproduces the repository byte for byte.
- `corpus check` lints for user-facing literals outside the declared sources.
- The `messages`, `table` and `exec` adapters, and the `corpus/1` snapshot contract with its ICU subset (placeholders and `select`).
- The package ships plain JavaScript for Node 22 with type declarations; a client's config imports `defineCorpus` from `@corpus-tool/cli`.
